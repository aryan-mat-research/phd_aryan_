Amur Tiger Re-identification Using Deep Learning

A technical study of individual tiger recognition from images, focused on the ATRW benchmark, transformer-based re-identification, fine-grained stripe features, image preprocessing, and exploratory CNN/GAN workflows.

01 / Overview

Technical objective and scope

The task is to determine whether two images or video frames show the same individual Amur tiger, despite changes in pose, viewpoint, illumination, background, scale, and camera location.

Unlike species classification, which predicts a category such as “tiger”, re-identification (re-ID) distinguishes individual identities within the same species. The primary visual cue is the spatial arrangement of body stripes, supported by other appearance cues. Non-rigid body motion can deform the visible stripe pattern, making alignment and robust feature representation central technical challenges.

01

Problem formulation

Given a query tiger image and a gallery of candidate images, rank gallery images by identity similarity and retrieve images belonging to the same individual.

02

Primary technical focus

Review transformer-based re-ID architectures and their combination with convolutional feature extraction and multi-granularity descriptors.

03

Exploratory implementation

Review notes and notebooks cover image preprocessing, a ViT learning attempt on flower images, and GAN-based tiger-image experimentation. These are separate levels of evidence and are not equivalent to a validated tiger re-ID model.

04

Project status

Literature review and exploratory coding. The supplied artifacts do not establish a completed, validated end-to-end tiger re-identification system.

Research questions

  1. RepresentationCan global self-attention features from a Vision Transformer complement local, fine-grained stripe features learned by convolutional and multi-granularity networks?
  2. Cross-camera generalizationHow do changes in camera, pose, lighting, and background affect retrieval performance compared with images captured by the same camera?
  3. Data scarcity and augmentationCan image transformations or generative augmentation increase visual diversity without changing tiger identity or introducing synthetic artifacts that harm retrieval?
  4. Evaluation integrityHow should mean average precision (mAP), cumulative matching characteristics (CMC), and Top-1 / Top-5 retrieval accuracy be used to compare methods?
02 / Dataset

ATRW: Amur Tiger Re-identification in the Wild

The ATRW dataset was introduced to support a full wildlife re-identification pipeline rather than a cropped-image-only identity benchmark. The original paper describes 8,076 high-resolution video clips from 92 Amur tiger identities, with annotations including bounding boxes, identity labels, and pose keypoints. The dataset includes varied poses, lighting conditions, and natural backgrounds.

Annotation and data organization

  1. Tiger detectionAnnotate a bounding box around each visible tiger. A detector can then filter irrelevant camera-trap frames and localize the animal before re-ID.
  2. View orientation and poseView orientation categories include frontal, left, right, and back. Skeleton keypoints provide a representation of body pose for alignment or part-based modeling.
  3. Identity and temporal metadataImages/crops are associated with identity and capture metadata such as camera ID, shot ID, and frame number. Such grouping matters when constructing train/test splits to reduce leakage between correlated frames.
  4. Re-ID gallery and queryA query image is matched against a gallery. Performance should be reported separately for single-camera and cross-camera cases where the benchmark protocol distinguishes them.
Dataset provenance: ATRW statistics in this section describe the published dataset, not a claim that all 8,076 clips or all annotations were processed by this project. The supplied DCGAN notebook separately reports 5,160 images loaded from a local “Amur Tigers” folder; the exact subset composition and identity split are not documented in the notebook.
03 / Methods

Re-identification pipeline and model families

The literature review compares conventional identity classification, metric-learning objectives, local/global alignment, pose-part modeling, and transformer-based feature extraction. The methods below are described as literature methods; they should not be interpreted as all having been independently implemented in the project.

3.1 Baseline: classification with cross-entropy

A backbone such as ResNet-50 maps a cropped tiger image to a feature representation, followed by an identity-classification head. In the reviewed baseline, the ResNet-50 backbone is frozen and only the added classifier is trained. The number of classifier outputs corresponds to the training identities (107 entities in the 2024 paper's described setup).

LCE = − Σc yc log pc

Here, y is the one-hot identity label and p is the predicted class-probability vector. The equation is a standard representation of cross-entropy, not a reported project-specific implementation.

3.2 Metric learning: triplet and batch-hard triplet loss

Triplet learning embeds an anchor image, a positive image of the same identity, and a negative image of a different identity. Training encourages the anchor-positive distance to be smaller than the anchor-negative distance by a margin.

Ltri = max(0, d(f(xa), f(xp)) − d(f(xa), f(xn)) + m)

Batch-hard mining selects challenging positive and negative examples within a mini-batch. This objective is directly relevant to retrieval because the embedding geometry—not only a closed-set class label—determines which gallery images rank nearest to the query.

3.3 Aligned re-ID and local/global distances

Aligned re-ID divides feature maps into horizontal parts and combines local part-level distances with a global distance. The reviewed report gives the local triplet-style term as:

Llocal = max(0, Dlocal(xa,xp) − Dlocal(xa,xn) + m)

The combined objective is reported as L = LTH + Llocal, where LTH is the batch-hard triplet term. Horizontal part alignment is a useful reference point, but tiger pose changes can make fixed partitions misalign corresponding stripe regions.

3.4 Pose-part-based modeling (PPbM)

Pose-part-based models use estimated keypoints to guide the extraction or alignment of body-part features. The reviewed ATRW work uses tiger-specific pose estimation and part modeling to address non-rigid pose variation. The literature notes that human pose estimators require adaptation to the tiger skeleton definition; pose estimation errors can propagate into re-ID.

3.5 Vision Transformer (ViT)

ViT divides an image into fixed-size patches, projects each patch into an embedding, adds positional information, and processes the sequence through transformer encoder blocks. Self-attention lets each patch representation use information from other image regions. A pooled or designated output representation is then used for classification or retrieval.

In the 2024 transformer-based tiger re-ID paper, preprocessed images pass through a shared ResNet-50 backbone; its feature maps are then processed by ViT to combine convolutional local features with global contextual relationships. This is the architecture described in the paper, not evidence of a successful ViT training run on tiger images in the user's notebook.

3.6 Multiple Granularity Network (MGN)

MGN learns descriptors at multiple spatial granularities, using global and part-level feature branches. The purpose is to retain fine-grained appearance cues at different scales. In the reviewed hybrid architecture, the ViT and MGN embeddings are concatenated so global contextual information and multi-granularity details can contribute to the final representation.

3.7 Neighbor Transformer (NFormer)

NFormer is a transformer-based re-ID architecture designed to model relationships among neighboring features. It was evaluated as a separate method in the 2024 paper. Its reported performance is a literature benchmark and does not represent a project-run result.

3.8 Retrieval refinement

Query expansion and re-ranking modify the initial query representation or the ordering of retrieved gallery candidates using information from top-ranked results. The reviewed paper evaluates these refinements with CMC curves and reports that the benefit varies by rank and model; a refinement may improve early ranks without improving the full rank range.

04 / Implementation

Image preprocessing and exploratory code

4.1 Preprocessing reported by the transformer-based paper

  1. ResizeImages are resized to 128 × 288 pixels using bicubic interpolation in the reviewed pipeline. This is the paper's reported input preprocessing; it is distinct from the 256 × 128 resolution described for some baseline methods.
  2. Random horizontal flipRandomly flip images horizontally to expose the model to mirrored appearances and improve robustness.
  3. ColorJitterApply randomized brightness, contrast, and saturation changes to reduce sensitivity to illumination and color variation.
  4. Tensor conversion and normalizationConvert images into tensors and normalize channels using the mean and standard deviation specified by the implementation. The exact normalization constants are not provided in the available report excerpt.
  5. Random erasingRandomly occlude image regions during training to improve resilience to partial occlusion. Exact probability and erase-area settings are not documented in the supplied notes.

4.3 TensorFlow/Keras GAN notebook

A second notebook loads Amur Tigers/reid_list_train.csv, uses TensorFlow/Keras layers to define a generator and discriminator, and includes a small custom GAN training loop. The recorded preview shows numeric identity-like values paired with image filenames. The notebook defines Adam optimizers at learning rate 0.0002 with β₁ = 0.5 and binary cross-entropy losses. The saved execution output includes a warning that the combined model has no trainable weights and very large loss values in an early iteration; therefore the run should be treated as debugging-stage exploration, not a successful trained generator.

The notebook's generator creates 224 × 224 × 3 outputs using dense layers and a tanh output; its discriminator begins with flattening the full image and dense layers. This design creates a very large parameter count and is not a conventional convolutional DCGAN discriminator. The captured model summaries report approximately 154.97 million generator parameters and 77.20 million discriminator parameters. The available output does not verify convergence or usable synthetic images.

4.4 Auxiliary CNN and augmentation experiment on flower images

A separate TensorFlow/Keras notebook uses the public flower-photo dataset to learn CNN classification and augmentation. This is a methodological exercise—not an Amur tiger re-ID result. The baseline CNN uses three convolution/max-pooling blocks (16, 32, 64 filters), a 128-unit dense layer, and a five-class output; it is trained for 30 epochs with Adam and sparse categorical cross-entropy. The training accuracy reaches approximately 99%, while test accuracy is 66.99%, indicating overfitting in the recorded run.

The augmented version adds random horizontal flipping, random rotation (factor 0.1), random zoom (factor 0.1), and dropout of 0.2 before the dense classifier. Its recorded test accuracy is 73.75% (loss ≈ 0.8419), an increase of about 6.75 percentage points over the baseline on that flower task. These numbers must not be presented as tiger identification performance or as evidence that augmentation improved tiger re-ID.

4.5 Vision Transformer learning attempt

The internship notes record an attempt to run a ViT model on the flower dataset, with the note “not got result.” The provided material includes transformer-concept notes (patch embeddings, positional embeddings, self-attention, query/key/value) but does not contain a verified training log, trained checkpoint, or validated evaluation for ViT on ATRW. No ViT accuracy is claimed for the user's implementation.

5.2 Metrics

mAP

Mean average precision

Measures ranking quality over relevant gallery matches across queries. It evaluates more than whether the first retrieved image is correct.

Top-1 / Top-5

Retrieval hit rate

Measures whether a correct identity appears within the first one or five ranked candidates.

CMC

Cumulative matching characteristic

Plots recognition rate against rank and helps show how query expansion or re-ranking changes early and later retrieval ranks.

Cross-camera

Generalization across views

Evaluates identity matching across cameras, where viewpoint, illumination, and capture conditions can differ.

06 / Limitations

Technical limitations and reproducibility gaps

  1. No verified ATRW training/evaluation runThe available files do not establish that a transformer or re-ID model was trained and evaluated on an identity-disjoint ATRW split. Published benchmark values must remain attributed to their authors.
  2. GAN notebook data leakage riskThe PyTorch notebook points both train and test datasets to the same folder. A valid evaluation requires a disjoint split and a clear protocol. The current discriminator accuracy loop also tests real/fake discrimination, not whether synthetic images preserve tiger identity.
  3. Generative training instabilityThe Keras GAN notebook records a “no trainable weights” warning for the combined model and large early losses. Training graph connectivity, trainability toggling, and generator/discriminator update steps need debugging before interpreting generated images.
  4. Identity-preserving augmentation is unverifiedGenerated samples could alter stripe topology or produce unrealistic texture. Before using synthetic images for re-ID, validate visual fidelity and identity consistency, and report performance on an untouched real-image test set.
  5. Dataset split and temporal correlationAdjacent video frames can be near duplicates. Splits should respect identity and capture metadata as required by the benchmark protocol to avoid optimistic leakage and unfair comparisons.
  6. Missing experiment metadataThere is no complete record of random seeds, exact dataset subset, class/identity counts, software versions, training curves, saved checkpoints, or reproducible query-gallery predictions for a tiger re-ID model.
07 / Next steps

Recommended technical workflow

  1. Audit and document the dataRecord the exact ATRW subset, file counts, identity labels, camera/shot/frame metadata, class balance, license/usage terms, and train/validation/test protocol.
  2. Establish a reproducible baselineStart from a published re-ID implementation with a documented ResNet-50 backbone and cross-entropy or triplet loss. Verify identity-disjoint splits and reproduce mAP, CMC, Top-1, and Top-5 before introducing augmentation.
  3. Validate the input pipelineUnit-test resizing, normalization, identity-label mapping, batch sampling, and query/gallery construction. Save a grid of transformed images and confirm labels remain unchanged after augmentation.
  4. Stabilize the GAN independentlyFix model trainability and update order, verify output shapes and loss gradients, save checkpoints, inspect generated samples at multiple epochs, and avoid using the same directory as train and test data.
  5. Test synthetic-data utilityCompare baseline real-only training against real-plus-synthetic training using the same held-out real test set. Report mAP and Top-k metrics with multiple seeds or confidence intervals, not discriminator accuracy alone.
  6. Run controlled ablationsCompare standard preprocessing, geometric/color augmentation, random erasing, and GAN augmentation separately. Keep model, split, sampler, training budget, and evaluation protocol fixed.
  7. Publish only reproducible resultsInclude source notebooks, environment requirements, configuration files, checkpoints where redistribution is permitted, and plots generated from saved evaluation predictions.
